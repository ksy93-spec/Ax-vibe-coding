# asset-inventory

폐쇄망 안에 이미 있는 자산이 어떤 구조인지만 뽑아내는 도구.

통합 포탈을 설계하려면 지금 무엇이 있는지 알아야 합니다. 그런데 소스 코드나 데이터를
밖으로 내보낼 수는 없습니다. 이 도구는 구조만 뽑습니다.

## 실행 환경

- Python 3.8 이상. 표준 라이브러리만 씁니다.
- 설치할 것 없음. 파일 하나입니다.
- openpyxl 없이도 xlsx 구조를 읽습니다 (zip + XML 로 직접 처리).

## 반입 방식

C. `inventory.py` 파일 하나만 옮기면 됩니다.

## 쓰는 법

클라우드 PC 에서, 통합 대상 폴더를 가리켜 실행합니다.

```
python inventory.py --root C:\작업폴더
```

`inventory_out\inventory.md` 와 `inventory.json` 이 생깁니다.
`run_inventory.bat` 을 더블클릭해도 됩니다 (현재 폴더를 조사합니다).

이름을 가리려면:

```
python inventory.py --root C:\작업폴더 --redact
```

파일명, 함수명, 시트명, 머리글이 8자리 해시로 바뀝니다. 같은 이름은 같은 해시라
중복 탐지는 그대로 동작합니다.

## 뽑는 것

| 대상 | 내용 |
| --- | --- |
| 전체 | 파일 종류별 개수, 크기, 수정일 |
| 파이썬 | import 목록, 함수 시그니처, 클래스와 메서드 이름 |
| 엑셀 | 시트 이름, 머리글 행, 행/열 수, 수식·매크로·외부연결 유무 |
| CSV | 인코딩, 구분자, 머리글, 행 수 |
| HTML/JS | 스크립트 참조, 외부 URL, 함수 이름, ES 모듈 사용 여부 |
| 의존성 | requirements.txt, package.json 의 패키지 목록 |
| 전체 | 중복으로 보이는 함수와 파일 |

## 뽑지 않는 것

코드 본문, 셀 값, 데이터 행, 주석 내용, 연결 문자열, 비밀번호.

머리글과 함수 이름은 구조 정보라 기본으로 포함합니다. 여기에 사내 용어가 들어갈 수 있으니
**내보내기 전에 `inventory.md` 를 직접 열어서 확인하세요.** 걸리는 게 있으면 `--redact` 로 다시 뽑습니다.

## 결과에서 먼저 볼 것

보고서 맨 위 "먼저 볼 것" 항목이 통합을 막는 것들입니다.

- **외부 URL**: CDN, 원격 폰트, 외부 API 를 쓰는 파일입니다. 폐쇄망에서 전부 실패하므로
  통합 전에 로컬 파일로 바꾸거나 걷어내야 합니다. 클라우드 환경에서 만들어진 코드라면
  여기 걸리는 게 꽤 나올 가능성이 높습니다.
- **ES 모듈**: `file://` 로 열면 CORS 로 막힙니다. 포탈을 파일로 열 계획이면 바꿔야 합니다.
- **구형 오피스 형식**: xls, doc, mdb 는 구조를 읽지 못합니다. 직접 확인이 필요합니다.
- **매크로**: xlsm 안의 VBA 로직은 이 도구로 보이지 않습니다. 별도로 확인하세요.
- **중복 함수**: 여러 사람이 같은 일을 각자 만든 자리입니다. 통합할 때 하나로 합칠 후보입니다.

## 검증 기록

2026-09-25. 파이썬 3개, 엑셀 2개(inlineStr 방식과 sharedStrings 방식, 빈 열 포함),
CP949/UTF-8 CSV, 68만 자 CSV, HTML, JS, 구형 xls, requirements.txt 를 섞은 폴더로 확인.
외부 URL 5개 호스트, 중복 함수, 매크로, 외부연결, 수식, 빈 열 위치까지 정확히 잡았습니다.
`--redact` 로 이름을 가려도 중복 탐지가 유지되는 것을 확인했습니다.
