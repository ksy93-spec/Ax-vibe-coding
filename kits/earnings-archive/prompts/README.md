# 사내 모델에 넘기는 프롬프트

두 갈래입니다.

- **자료 만들기** (매 분기): 녹취록과 보도자료를 사내 모델에게 주고 이 도구가 읽는 JSON 을 받습니다.
  평소에는 도구의 자료 넣기 탭이 프롬프트를 만들어 주므로 이 폴더를 열 일이 없습니다.
- **도구 고치기** (가끔): 화면에 표나 지표를 더하거나 오류를 고칠 때 씁니다.

| 파일 | 언제 |
| --- | --- |
| `10-call-summary.md` | 녹취록 -> 콜 요약 JSON. 도구를 못 쓸 때, 템플릿을 고칠 때 |
| `11-numbers.md` | 보도자료 -> 숫자 JSON. 위와 같음 |
| `../READMEChatGPT.md` | 도구 고치기 전에 먼저 읽기. 모듈 지도, 자주 하는 변경의 파일 순서, 요청 양식 |
| `00-project-instructions.md` | 도구 고치기 처음 한 번. ChatGPT 프로젝트 지침에 붙여 넣습니다 (READMEChatGPT.md 2절이 더 자세함) |
| `20-screen-change.md` | 화면에 표, 지표, 차트를 더할 때 |
| `40-fix-error.md` | 테스트 실패, 콘솔 오류가 났을 때 |

## 자료 만들기 요령

- 조각마다 새 대화창을 엽니다. 같은 대화창에서 이어 시키면 앞 조각 내용이 섞입니다.
- 답이 중간에 끊기면 자료 넣기 2번의 "조각 최대 글자 수" 를 줄여 다시 만듭니다 (24,000 -> 12,000).
- 검사에서 빨간 항목이 나오면 오류 문장을 그대로 모델에게 주고 "이 오류를 고친 JSON 전체를 다시 줘" 라고 합니다.
- 넣은 뒤 원문과 숫자를 대조하고 편집에서 상태를 "확인" 으로 바꿉니다. 단위 실수(billion 과 million, 조와 억)가 가장 흔합니다.
- 녹취록 원문은 사내 모델과 사내 data 폴더에만 둡니다. 바깥 저장소에 올리지 않습니다.

## 도구 고치기 (ChatGPT Enterprise)

1. 프로젝트를 만들고 지침(Instructions)에 `00-project-instructions.md` 의 코드 블록을 붙여 넣습니다.
2. 프로젝트 파일로 `SPEC.md`, `types/ea.d.ts` 를 올립니다.
3. 대화마다 20 이나 40 을 골라 빈칸(〈 〉)을 채워 붙여 넣고, 고칠 파일 전체를 같이 붙여 넣습니다.

Cline 은 20, 40 본문을 그대로 붙여 넣습니다. 파일은 Cline 이 직접 열고, 규칙은 `.clinerules` 에서 읽습니다.

- 한 번에 파일 하나.
- `src/model/` 을 고쳤으면 `tests/index.html` 을 열어 전부 통과하는지 봅니다.
