# 설치와 실행

설치할 것이 없습니다. 인터넷도 필요 없습니다.

## 1. 압축 해제

한글과 공백이 없는 경로에 풉니다. 예: `C:\work\web-tool-starter`

## 2. 실행

`index.html` 을 더블클릭합니다. 끝입니다.

Chrome, Edge, Firefox 모두 됩니다. 인터넷 익스플로러는 안 됩니다.

### 로컬 서버로 여는 경우

`file://` 에서 막히는 기능이 필요해지면 (예: `fetch` 로 로컬 JSON 읽기) 서버로 엽니다.
사내 PC 에 Python 이 있으면 `serve.bat` 을 실행하고 브라우저에서 `http://localhost:8000` 을 엽니다.
Python 이 없으면 `file://` 로 쓰세요. 이 킷의 기능은 전부 `file://` 에서 동작합니다.

## 3. 확인

아래가 모두 맞으면 정상입니다.

- [ ] 글꼴이 시스템 기본 고딕이 아니라 Pretendard 로 보인다 (숫자와 한글 폭이 고르게 보임)
- [ ] CSV 파일을 끌어다 놓으면 표가 뜬다
- [ ] 열 제목을 누르면 정렬된다
- [ ] 검색창에 입력하면 행 수가 줄어든다
- [ ] 내보내기로 받은 CSV 를 엑셀에서 열었을 때 한글이 깨지지 않는다
- [ ] 브라우저 콘솔(F12)에 빨간 에러가 없다

## 문제가 생기면

**글꼴이 기본 고딕으로 보인다**
`assets/fonts/PretendardVariable.subset.woff2` 가 있는지 확인하세요.
압축을 풀 때 빠지거나, 전송 중 바이너리가 깨졌을 가능성이 큽니다.

**표가 안 뜨고 콘솔에 `App is not defined`**
`index.html` 의 스크립트 순서가 바뀌었습니다. `dom.js` 가 가장 먼저,
`main.js` 가 가장 마지막이어야 합니다.

**한글이 물음표나 깨진 글자로 보인다**
CSV 원본 인코딩이 CP949 도 UTF-8 도 아닌 경우입니다. 원본을 엑셀에서 열어
`CSV UTF-8` 로 다시 저장한 뒤 넣어 보세요.

**엑셀에서 열었더니 한글이 깨진다**
이 킷의 내보내기가 아니라 다른 경로로 만든 파일일 가능성이 큽니다.
`App.csv.download` 를 거치면 BOM 이 붙습니다.

**`Cross origin requests are only supported for HTTP` 에러**
누군가 `<script type="module">` 을 추가했습니다. `file://` 에서는 쓸 수 없습니다.
클래식 스크립트로 되돌리거나 로컬 서버로 여세요.
