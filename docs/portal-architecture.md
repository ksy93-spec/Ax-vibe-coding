# Market Intelligence 통합 포탈 설계안

1차 프로젝트. 여러 사람이 클라우드 환경에서 각자 만들어 둔 기능을 한 곳에서 보게 만드는 일입니다.

## 통합하지 말고 감쌀 것

가장 흔한 실패는 기존 코드를 하나의 프로그램으로 다시 쓰려는 것입니다. 이 환경에서는 특히 위험합니다.

- 원래 만든 사람이 계속 고칠 텐데, 다시 쓰면 그 사람의 갱신이 포탈에 안 들어옵니다.
- 사내 모델은 남의 코드 여러 개를 한꺼번에 리팩터링하는 작업에서 가장 크게 무너집니다.
- 한 번에 다 바꾸면 무엇이 깨졌는지 추적이 안 됩니다.

그래서 기존 산출물은 그대로 두고, 포탈이 그 위에 얹히는 구조로 갑니다.
각 기능은 자기 자리에서 계속 돌고, 포탈은 결과만 모아 보여줍니다.

## 두 개의 층

```
  [수집/가공 층]  각자의 파이썬 스크립트, 엑셀, 쿼리
        |
        |  약속된 형식으로 결과를 내놓는다
        v
  data/<모듈이름>/data.js
        |
        v
  [표시 층]  포탈 (브라우저 한 화면)
```

수집 쪽은 지금 쓰는 방식을 유지합니다. 파이썬이면 파이썬, 엑셀이면 엑셀입니다.
바뀌는 건 결과를 내놓는 자리와 형식뿐입니다.

## `data.js` 로 내보내는 이유

브라우저에서 `file://` 로 연 페이지는 로컬 JSON 을 `fetch` 로 읽지 못합니다. CORS 로 막힙니다.
사내 공용 웹서버가 없다면 이게 바로 걸립니다.

JSON 대신 JS 파일로 내보내면 `<script>` 태그로 읽히므로 이 문제가 사라집니다.

```js
// data/price_monitor/data.js
window.__PORTAL__ = window.__PORTAL__ || {};
window.__PORTAL__["price_monitor"] = {
  "updated_at": "2026-09-25 09:00",
  "owner": "박과장",
  "title": "원자재 가격 모니터",
  "columns": ["품목", "단가", "통화", "기준일"],
  "rows": [["강판", 1200000, "KRW", "2026-01-02"]],
  "summary": [{"label": "전주 대비", "value": "+3.2%", "tone": "warn"}]
};
```

파이썬 쪽에서는 `json.dumps` 결과를 이 한 줄로 감싸 파일로 쓰면 끝입니다.
사내 공용 웹서버를 쓸 수 있게 되면 그때 `fetch` 방식으로 바꿔도 포탈 쪽 변경이 작습니다.

## 모듈 계약

각 모듈은 폴더 하나입니다. 파일도 하나입니다.

```
data/
  modules.js              띄울 모듈 목록. 순서가 곧 사이드바 순서
  price_monitor/
    data.js               지표, 차트, 표가 한 파일에
  competitor_news/
    data.js
```

별도 `module.json` 은 두지 않았습니다. `file://` 에서는 JSON 을 읽을 방법이 없어서
어차피 JS 파일이어야 하고, 파일이 둘이면 둘 사이가 어긋날 수 있습니다.

`data.js` 하나에 지표 카드(`kpis`), 차트(`charts`), 표(`table`)를 적으면 포탈이 그립니다.
Market Intelligence 용도는 이 셋으로 대부분 덮입니다.

새 기능을 붙일 때 포탈 코드를 안 고쳐도 됩니다. 폴더를 만들고 `data.js` 를 넣으면
화면에 뜹니다. 사내 모델에게 시킬 작업 단위도 "모듈 하나"로 깔끔하게 쪼개집니다.

## 진행 순서

1. **현황 파악.** `kits/asset-inventory` 를 클라우드 PC 에서 돌립니다.
   무엇이 있는지, 어디가 겹치는지, 외부 URL 을 쓰는 게 무엇인지 나옵니다.
2. **계약 확정.** 위 형식을 실제 데이터에 맞게 손봅니다. 이건 `specs/` 에 적습니다.
3. **포탈 셸 제작.** 이 저장소에서 만듭니다. 모듈이 0개여도 도는 빈 포탈입니다.
4. **모듈 1개 연결.** 가장 단순한 기능 하나를 먼저 붙여 봅니다.
   이 단계에서 계약의 구멍이 드러납니다. 여러 개를 동시에 붙이지 마세요.
5. **나머지 확장.** 모듈마다 담당자가 `data.js` 를 내놓게 합니다.

3번은 `kits/portal-shell` 로 끝났습니다. 모듈이 0개여도 도는 빈 포탈이고,
샘플 모듈 2개가 들어 있습니다. 남은 것은 1번, 2번, 4번입니다.

## 정해진 것

- 포탈은 각자 PC 에서 `file://` 로 엽니다. 그래서 `data.js` 방식이 필수입니다.
- 클라우드 PC 에 git 이 없다고 보고, 작업 전 폴더 복사로 원본을 남깁니다.
