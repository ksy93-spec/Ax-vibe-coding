# 망 구조와 자료 흐름

## 세 구역

```
  [1] 외부 (이 저장소, Claude)
       |
       |  git push / clone          <- 로컬망 PC 에서만 가능
       v
  [2] 사내 로컬망 PC
       |
       |  zip 파일 전달
       v
  [3] 사내 클라우드 PC             <- 실제 개발과 실행이 일어나는 곳
       - Qwen 3.5-Cline (VS Code)
       - ChatGPT Enterprise
       - 다른 사람들이 만들어 둔 기존 기능
       - GitHub 접속 완전 차단
```

로컬망 PC 가 중계소입니다. 여기만 양쪽에 닿습니다.

## 들어가는 방향 (외부 -> 클라우드)

1. 로컬망 PC 에서 이 저장소를 clone 하거나 pull 합니다.
2. `scripts/pack.sh <킷이름>` 으로 압축하거나, 저장소 폴더를 통째로 zip 으로 만듭니다.
3. 클라우드 PC 로 전달합니다.

로컬망 PC 에서 clone 이 되므로 킷을 매번 수동으로 내려받을 필요가 없습니다.
`git pull` 한 번이면 여러 킷이 한꺼번에 갱신됩니다.

## 나오는 방향 (클라우드 -> 외부)

**기본은 나오지 않는 것입니다.** 다음은 외부로 내보내지 않습니다.

- 소스 코드 본문
- 실제 데이터, 데이터 일부, 스크린샷
- 사내 시스템 주소, 계정, 테이블명, API 명세
- 사번, 이름, 조직도

통합 설계에 필요한 것은 코드 본문이 아니라 구조입니다. 그래서 다음만 가져옵니다.

- 무엇이 몇 개 있는지 (파일 종류, 개수, 규모)
- 어떤 함수와 시트가 있는지 (이름과 시그니처, 본문 제외)
- 무엇에 의존하는지 (import 목록, 외부 URL 사용 여부)
- 어디가 겹치는지 (여러 사람이 같은 일을 중복으로 만들었는지)

`kits/asset-inventory` 가 이것만 뽑아냅니다. 뽑아낸 결과도 그대로 내보내지 말고
**반출 전에 직접 열어서 확인하세요.** 사내 용어가 함수 이름이나 시트 이름에 들어 있을 수 있습니다.
가려야 할 게 있으면 `--redact` 로 이름을 해시로 바꿔 다시 뽑습니다.

판단이 서지 않으면 내보내지 말고, 그 부분은 설명만 말로 전해 주세요.
구조를 말로 듣고도 설계는 됩니다.

## 클라우드 PC 안에서의 버전 관리

여러 사람의 산출물을 합치는 작업입니다. zip 을 주고받으며 합치면 누가 무엇을 언제 바꿨는지
금방 추적이 안 됩니다. 클라우드 PC 에 git 이 설치되어 있다면 원격 없이 로컬 저장소만으로도
충분합니다. git 은 네트워크 없이 완전히 동작합니다.

```
git init
git add -A
git commit -m "통합 전 원본"
```

원본을 한 번 커밋해 두고 시작하면, 통합하다 깨졌을 때 되돌릴 수 있습니다.
이것만으로도 통합 작업의 위험이 크게 줄어듭니다.

git 이 없으면 최소한 작업 시작 전 폴더를 통째로 복사해 `_원본_날짜` 로 남겨 두세요.
